Guided setup

Four steps to your first ring

  1. 1

    Install the verified CLI

    The installer detects your architecture, downloads the latest stable archive, verifies SHA256SUMS, and installs only your selected shell integration.

  2. 2

    Pair this machine

    Run the command, then approve the pairing code in your private Shellbell web app.

  3. 3

    Register receivers

    Open the relay URL, install the PWA, allow notifications, and tag each receiver as phone, pc, mobile, or desktop.

  4. 4

    Validate end to end

    Doctor checks the local daemon, source credentials, relay connectivity, durable queue, and shell integration. The ring verifies delivery.

Self-hosting

Own the relay

Use a Linux VPS or Docker host, your own domain, and the published Shellbell image. The commands below keep the relay on loopback and expose only HTTPS through Caddy.

Full deployment docs ↗
Before you begin

Point your domain's A or AAAA record at the host, allow inbound TCP 80 and 443, and install Docker Compose, Caddy, curl, OpenSSL, Node.js/npm, and jq. Port 8080 must not be publicly exposed.

  1. 1

    Create the private stack directory

    Download the reviewed Compose definition into a root-owned application location while keeping day-to-day edits available to your current administrator account.

  2. 2

    Generate owner and Web Push secrets

    The token and VAPID keys are generated on your server. The page never receives or stores them. Keep the resulting .env file private and out of Git.

  3. 3

    Start and validate the relay

    Compose pulls the stable multi-architecture image, starts the relay, and verifies its loopback-only health endpoint before public exposure.

  4. 4

    Put HTTPS in front with Caddy

    This creates a dedicated site file, validates the complete Caddy configuration, reloads it, and checks the public health endpoint.

  5. 5

    Claim the owner session

    Open the relay, paste the locally retrieved bootstrap token into the owner sign-in form, install the PWA, and register your first receiver.

Privacy boundary

Shell activity, not shell contents.

Shellbell does not collect commands, output, exit codes, environment variables, working directories, process lists, or inferred success and failure.
